# KEE 知识图谱是如何实现的

KEE 是一套可离线部署的企业知识工程底座：文档进来之后，先变成「文档自己说了什么」，再按本体对齐成可查询的事实，并在双时态账本上保留「世界何时为真」与「系统何时相信」两条时间轴。

权威设计见仓库内 `docs/design/` 与 `docs/decisions/`（尤其是 [0044](../docs/decisions/0044-the-ontology-is-a-view-over-what-documents-say.md)）。下文是实现向的总览。

---

## 1. 三层模型（核心）

| 层 | 存什么 | 是否依赖本体 |
|---|---|---|
| **开放图谱（open graph）** | 实体、类别词、用文档原话写的陈述、引文、时间说法、别名 | 否 |
| **本体（ontology）** | 类、关系/属性、约束、继承、时态语义等词表 | 自身即词表 |
| **类型化图谱（typed graph）** | 用本体属性表达的事实，由开放图谱对齐/物化而来 | 是 |

抽取**只写开放图谱**，提示词里不放本体。本体变更时，不必整库重抽：只对受影响的签名与规则重新物化。

```text
文档 / 来源
    │  ingest：解析 → 分块 → 全文索引 + 向量
    ▼
开放陈述（entities / open statements / quotes / time mentions）
    │  alignment：短语签名 → 绑定 / 蕴含规则（人工确认）
    ▼
类型化事实（facts，带 valid_* 与 recorded_*）
    │  reason：公理前向链派生 derived_facts
    ▼
检索 / 对话 / 图谱浏览 / MCP 工具
```

---

## 2. 从文档到开放图谱

### 2.1 摄入

- **入口**：上传（PDF / Office / HTML / Markdown 等）、RSS、GitHub、Jira、Notion、WebDAV、S3 兼容桶，以及 API。
- **实现**：`utopia-ingest` 负责解析与分块；`utopia-server` 的 pipeline / sources 调度同步与任务。
- **落库**：文档与分块在 Postgres；全文在进程内 **Tantivy**（`data/index/`）；向量在 **pgvector**（分块 embedding）。

分块边界就是抽取能看见的全部上下文（决定 0039）：切掉的内容无法靠提示词补回。

### 2.2 开放抽取

- **契约**：`utopia-extract::open` —— 每个分块一次 LLM 调用（温度 0）。
- **输出**：`e` 实体（名字或描述 + 文档自己的类别词）、`s` 陈述（原话关系短语、主语/宾语、限定语、`when`/`ended`）、`n` 别名；每条陈述自带 verbatim 引文。
- **服务端**：`utopia-server` 的 `extraction_open`：流式调用（避免推理时读超时）、限流退避、引文/名字必须在分块中出现等硬校验；失败写入 `extraction_drops`，文档不会假装「抽完了」。

记忆类文档走同一条开放路径，但陈述先进入待确认表，等人点头才入账（0015）。

---

## 3. 从开放图谱到类型化事实

### 3.1 对齐（alignment）

按**签名**决策，而不是按单条事实：

- 签名大致是：关系短语 + 主语类 + 宾语类。
- 产物：
  - **绑定（binding）**：该签名对应哪个本体属性、方向如何；缓存后复用。
  - **蕴含规则（implication）**：某形状的陈述可推出另一属性的事实；对短语的「读法」（如国籍形容词 → 国家）按短语缓存，物化时不再调模型。

人工在审阅台确认；确认与物化任务同一事务挂起（0051 方向）。

### 3.2 物化（materialize）

`utopia-store::materialize` 读开放陈述 + 已批准绑定/规则 → 写出 `facts`（及蕴含标记的 implied 行）。本体或绑定变了，只重算相关签名。

### 3.3 勘误代理（errata）

结构异常优先（类型越界、引文对不上、日期属性无日期等），再抽样；经治理闸门改写/撤回，并留下可回滚的决策记录。

## 4. 双时态与身份

### 4.1 两条时钟

| 轴 | 列 | 含义 |
|---|---|---|
| **世界轴（valid）** | `valid_from` / `valid_to`（及精度） | 事实在现实中何时成立 |
| **记录轴（recorded）** | `recorded_at` / `invalidated_at` | 系统何时相信 / 何时作废 |

读取统一走 `world_axis` / `record_axis`，带 `at`（世界时刻）与 `as_of`（记录时刻）。改正事实是**闭合旧行 + 追加新行**，不是原地覆盖。

未写明起止时，用证据文档日期作锚（`attested_from` / `attested_to`），避免「没写开始就当成自古成立」。

### 4.2 实体身份

名字本身是事实（0041）。候选来自同名/别名与名字向量；确定性证据能定的先定，不定的进裁决；合并可撤销，聚类遵守 cannot-link。

## 5. 本体、推理与冲突

- **冷启动**：建库时可勾选打进二进制的 pack（schema.org、W3C Org、PROV-O、FOAF、IOF Core）；也可导入 OWL；也可在工作台手改。
- **推理**：`utopia-reason` 把传递、对称、逆关系、关系层级等编成规则，前向链写入 `derived_facts`；派生事实可展示证明链；与断言冲突时断言优先。默认关闭，避免错误公理放大错误。
- **冲突**：时序接替 vs 同时两值、公理违反（自环、基数等）、本体自检缺陷，分队列治理；自动动作受「能否撤销」闸门约束（0025 / 0027）。

---

## 6. 对外能力（图谱之上）

- **检索**：Tantivy 全文 + pgvector 向量，RRF 融合；对话带可点开原文的引用。
- **对话 / Agent**：搜文档、按时刻走图谱、查挂载库；只读工具经 **MCP** 暴露。
- **Ontology2SQL**：把库表映射到本体后，可用本体语义查结构化数据。
- **审计**：确认/拒绝、合并/回滚、重建等写入 append-only 决策账本。

---

## 7. 运行时形态

- **一个 Rust 二进制**（`utopia-server`）+ **一个 Postgres（含 pgvector）**。
- 任务队列是表；全文索引在进程内；LLM 为任意 OpenAI 兼容端点（可完全内网）。
- 前端 `web/`（Vite + React）提供控制台、图谱浏览器、本体工作台。
